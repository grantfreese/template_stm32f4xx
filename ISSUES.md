# STM32F4 Template Issues

## T2: Dead-code audit of src/ and driver/
**Status**: `to-do`

**Description**:
Sweep the template for dead code: implemented-but-unreachable classes, functions never called, files never
included, and comments referencing features that do not exist. Known examples: fw::TaskStats is a complete class
with no includers (T1 wires it up), the ADC1 debug streamer had no producer (B1), src/version.h.in appears
unused since the version header is generated by the build from scripts/get_version.sh, and task_cli.h documents
a 'status' command that is not implemented. The audit distinguishes true dead code from intentional template
surface (e.g. the ads131m0x driver is deliberately not instantiated; board projects supply the SPI bus).

**Implementation Details**:
To be fleshed out before starting. Sketch: cross-reference symbols with the linker map / --gc-sections removal
list and arm-none-eabi-nm, plus grep for never-included headers; classify each finding as delete, wire up, or
intentional-template-surface; deliver the classification in the ticket and file follow-up tickets for removals
or fixes rather than deleting inline.

**Acceptance Criteria**:
- A complete findings list covering src/ and driver/ (vendored HAL/CMSIS excluded), each entry classified with a
  recommendation.
- No code changes on this ticket beyond the report unless separately approved.

**Testing**:
- Not applicable beyond a clean build; the deliverable is the audit report. Follow-up tickets carry their own
  testing.

## T1: 'status' CLI: task loop stats and stack usage
**Status**: `to-do`

**Description**:
fw::TaskStats (src/tasks/task_stats.h) is fully implemented but never instantiated, and no CLI command reports
task health. Add a cross-cutting 'status' command that reports per-task loop statistics and stack usage so
bench sessions can see scheduler health without a debugger.

**Implementation Details**:
To be fleshed out before starting. Sketch: instantiate fw::TaskStats in the CLI and CAN task loops, calling
RecordTick() with measured iteration duration against each task's target period; add src/cli/cli_status.cpp
(cross-cutting module per the CLI file-organization rules) registered via the weak-registrar pattern and
cmake/cli_features.cmake; 'status' prints, per task: loop count, min/avg/max iteration time, deadline misses,
and stack peak from uxTaskGetStackHighWaterMark() against the declared stack size. Update the stale
kStackSizeWordsCli comment in task_cli.h that already refers to the 'status' command.

**Acceptance Criteria**:
- 'status' lists every task with loop statistics and stack usage (peak words used, declared size, percentage).
- Deadline-miss counts increment when a task overruns its period.
- Stats survive continuously (no reset on read) unless an explicit reset argument is provided.

**Testing**:
- Bench serial session: run 'status', verify both tasks appear with plausible loop times (CLI ~50 ms, CAN
  ~100 ms) and stack percentages below 100; confirm counts grow between invocations.

## B1: 'debug adc1' never streams; add die-temperature streaming
**Status**: `to-do`

**User Description**:
The debug streaming on adc1 does not work. I want to be able to stream the temperature we read over the ADC.

**Description**:
`debug adc1` toggles its flag and the streamer (driver/adc1/debug_adc1.cpp) is compiled in, but nothing ever
calls DebugStageAdc1() -- there is no producer, so enabling the flag yields no output. The CAN task reads the
die temperature every second yet stages nothing to this streamer, and the streamer's print format only covers
volts plus raw counts, with no temperature form.

**Implementation Details**:
To be fleshed out before starting. Sketch: stage the die-temperature sample (raw counts and degrees Celsius)
from the CAN task's periodic read; extend or rework the ADC1 streamer output to print temperature. Decide how
the staging cadence interacts with `debug rate` versus the fixed 1 Hz sampling.

**Acceptance Criteria**:
- With `debug` and `debug adc1` enabled, die-temperature lines stream periodically on the CLI and stop when
  either flag is toggled off.

**Testing**:
- Bench serial session: toggle the flags, verify temperature lines appear with plausible values and match the
  `can` status output; verify silence after toggling off.
